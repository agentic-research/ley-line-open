Section: Breaking
- **Wire break, `wire_format_major` 3: `query` rows are lists of typed cells in `columns` order, not objects keyed by column name, and truncation is a declared field** (beads `ley-line-open-0a18bc`, `ley-line-open-47d5c5`). A keyed row lost a value whenever two columns shared a name: `SELECT 1 AS id, 2 AS id` answered `[{"id": "2"}]`. Each row is now a list of `QueryCell` unions, one per column in `columns` order, so that query answers `[[{"text": "1"}, {"text": "2"}]]`. A cell is `{"null": null}` for SQL NULL or `{"text": "..."}` for every other value, so NULL is carried by the schema and stays distinct from `""`. Values keep their text rendering (integers and reals in decimal, blobs as lowercase hex); typed members are the intended additive extension. A client that reads `row[column_name]` must read `row[i]` for the column's index and branch on the cell's member. In `daemon.capnp`, `QueryResponse.rows` is a new field (@5, `List(List(QueryCell))`), and the old @2 is retired as `retiredRows` (`retired_rows`), never emitted. A reply cut short by the row limit now carries `truncation: {"limit": N}` (`QueryResponse.truncation` @6, struct `QueryTruncation`), absent otherwise; the undeclared `truncated: true` and `limit: N` keys are gone. `QueryRequest.limit` is declared as `UInt32`: absent or 0 means the default of 1000, and a larger value than `UInt32` holds is refused with the new refusal reason `limit_out_of_range` (`action` `limit`, `subject` the requested value) before anything runs, never clamped. The daemon encodes the whole `query` success response with the schema's JSON codec and no longer patches its JSON. `wire_format_major` moves from 2 to 3, so a major-2 client fails the version handshake instead of misreading rows; `compat_min_schema_version` stays 0.6.0, because the major does the refusal. In the Go module, `wire.QueryResponse.Rows` is `[][]wire.QueryCell`, `wire.QueryResponse.Truncation` is a `*wire.QueryTruncation`, `wire.QueryRow` is removed, and `wire.QueryCell` refuses anything but exactly one known member, a member repeated under one key included. The Go drift gate no longer skips `query`. A new gate, `task schema:daemon-fixture-codec`, round-trips every daemon protocol fixture through `daemon.capnp` with the reference capnp JSON codec and requires the same JSON types back (`0` is not `0.0`), refuses a `retired_*` key, and looks each fixture's struct up in a declared table pairing every Go binding with its capnp struct, which must match the Go gate's decoders. It found that the `sheaf_invalidate` fixture and the Go test mirror both omitted `prior_generation`, which the daemon sends, and that the `sheaf_defect` and `sheaf_status` fixtures wrote `defect` as `0.0` where the daemon writes `0`; all are fixed. Text cells holding NUL and control characters round-trip through the Rust codec, the reference codec and the Go decode.
