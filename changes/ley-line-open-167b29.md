- **CAS volume provisioning bounds each `hdiutil` run, cleans up after a crashed provider, and uses only its own image** (bead `ley-line-open-167b29`). Each `hdiutil` run is killed after `DEFAULT_TOOL_TIMEOUT` (120 s, `Hdiutil::with_timeout` to change it) and fails as the new `CasVolumeError::Timeout`, instead of hanging provision while it holds the volume's lock. A `partial-<pid>.sparsebundle` left by a provider that crashed between create and rename is removed once that process is gone. A filesystem mounted at `<state>/cas-volume/mnt` is used only when `hdiutil info` names `cas.sparsebundle` as its image, and is otherwise refused as the new `CasVolumeError::ForeignVolume`. Provisioning also takes a file lock (`<state>/cas-volume/provision.lock`), so two processes take turns. `DiskImages` gains `attached_image`; its default refuses. An exhaustive `match` on `CasVolumeError` must add the two new variants.
