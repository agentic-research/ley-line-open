Section: Security

- **A rootfs digest now names one guest tree: the per-run copy holds exactly the directories the manifest implies, each at `0755`** (bead `ley-line-open-38ff59`). Rootfs manifest v1 authenticates files only, yet `materialize_ephemeral_rootfs` copied every directory of the CAS entry with its mode into the guest, so anyone able to write the CAS root could widen a directory (world-writable, setgid, sticky) or plant one and the digest still resolved. The per-run copy is now built from the manifest: the listed files and their parent directories, every directory (the root included) at `0755`, nothing else; a file in a directory the manifest does not imply is refused as undeclared, and `verify_ephemeral_rootfs`, run again before VM entry, refuses a copy whose directories are not exactly that set at `0755`. `DirectoryRootfsResolver` still accepts any directories in a CAS entry, since v1 does not name them. A guest no longer sees an empty directory a hand-built CAS entry carried (an empty `tmp/`, for one); the guest init's own mounts (`/dev`, `/proc`, `/sys`, `/tmp`) are unaffected.
