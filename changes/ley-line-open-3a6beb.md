Section: Changed

- **Work lands on `integration` through `task land:integration`, gated on the local `task ci` receipt, and pull requests into `integration` no longer run `ci.yml` or `leyline-schema-go.yml`** (bead `ley-line-open-3a6beb`).
  `tools/land_integration.sh` refuses, each by name, a working tree that differs from HEAD (`dirty-tree`), a branch that does not contain `origin/integration` (`integration-not-in-head`) and a tree with no `task ci` receipt for the current toolchain (`no-receipt`); otherwise it fast-forwards `integration`, never forced. `task ci:land-integration:fixture-test`, run by `task ci`, proves each refusal and the fast-forward. `task ci` now also runs the Go schema module's regen diff and full `go test ./...` (`schema:go:regen-check`, `schema:go:test`, with `deps:capnpc-go` installing the pinned generator), which before ran only in `leyline-schema-go.yml`. The pre-push receipt gate (`tools/pre_push_ci.sh` and its pre-commit hook) is removed: it never ran under the repository's rsry hooks path, so it guarded nothing. `ci.yml` and `leyline-schema-go.yml` run on pull requests into `main` only; their push triggers are unchanged. `ci.yml` gains `workflow_dispatch`: the receipt covers only the platform `task ci` ran on, so a change with platform-specific code asks the runner for Linux evidence on its branch before landing (`gh workflow run ci.yml --ref <branch>`). `mutants.yml` still runs on pull requests into `integration`: `task rs:mutants:pr` writes no receipt the landing gate could check, so that runner job remains the only recorded mutation evidence until per-task receipts exist (`rosary-3a84a9`).
