Section: Fixed

- **A microVM guest receives exactly the argv and environment its request names** (beads `ley-line-open-7410ec`, `ley-line-open-d4b07f`, `ley-line-open-f7f862`). libkrun handed both to the guest on the kernel command line, which the kernel and the guest init re-parse.
  - **What broke.** An argument `--` cut the argv there, so an image entrypoint like `tini -- docker-entrypoint.sh` ran with no program. A double quote was consumed or ended its argument (`sh -c 'x="ab"; exit 93'` exited 2). A word inside an environment value, such as `x tsi_hijack y`, could be read as an init token.
  - **The fix.** The worker writes the workload's argv and environment as JSON to `/.leyline-exec.json` in the run's own root. It writes the file after the root's last verification and before the VM exists, exclusively and never through a link. The guest init execs exactly that (new LLO libkrun patch `0013`, `KRUN_CONFIG_ARGV=1`) and removes the file. The kernel command line keeps only worker-chosen tokens.
  - **Every byte arrives.** `"`, `\`, `'`, newlines, tabs, all control characters U+0001 to U+001F, `--` and multi-byte UTF-8 arrive byte for byte. Patch `0013` also fixes the init's `\uXXXX` decoder, which mangled every control character JSON escapes that way, and reads the file until all of it is in.
  - **Admission.** An environment key may now be any name an environment can hold (lowercase and dots included). What is still refused by name: a key that is empty or holds `=`, a NUL, any `KRUN_` key (the init's own settings), more than 16,000 strings, a string of 128 KiB or more, or more than 1 MiB in all. The executable still rides the command line, so it stays printable ASCII with no space or quote.
  - The native tier execs argv directly and is unchanged.
