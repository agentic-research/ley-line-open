Section: Changed
- **The vendored libkrun moves from v1.19.6 to v1.19.8, and LLO's patch series from 16 patches to 14** (bead `ley-line-open-b1236b`). `rs/third_party/libkrun` is now upstream v1.19.8 (`c4d283c2`), fetched from `libkrun/libkrun`, which `containers/libkrun` redirects to. Patch `0001` (start the macOS mapping worker for virtio-fs DAX windows) is dropped because v1.19.8 starts that worker on every macOS VM (upstream #941). Patch `0016` (a guest that records no exit status does not exit 0) is replaced by upstream's `krun_set_reset_exit_code`, which the worker calls with 125 in `prepare_vm`. A kernel panic, an init death and a workload run as PID 1 exiting still end the run `Failed` with exit status 125, and a status the guest recorded still wins. Two things change: the VMM no longer explains the 125 on its stderr, and a guest that powers off without recording a status exits 0. Only guest root can power the guest off, and it could record 0 itself just as easily. v1.19.8 also brings upstream's stable fixes, among them the PL031 clock across host sleep and the macOS READDIRPLUS fixes. Patches `0008` and `0011` were re-exported against the new context, with their logic unchanged.
