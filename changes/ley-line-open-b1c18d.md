Section: Security

- **A registry pull no longer follows a token realm or redirect to a loopback, private or link-local address, and a header trickle is cut at a deadline** (bead `ley-line-open-b1c18d`). A registry chooses its token realm and its redirects, so it could steer `leyline rootfs import-oci --from-registry` into GETs to the host's own or its network's HTTPS services. A connection to any endpoint other than the registry the reference names, or the loopback authority `--insecure-plain-http-registry` names, must now resolve to public addresses only: loopback, RFC 1918 and unique-local, link-local, CGNAT, unspecified, multicast, documentation, benchmarking and reserved ranges (and an IPv4-mapped or NAT64 form of one) are refused before a socket is opened, on the addresses the connection would use, so a name that resolves to one is refused like a literal. The new `OciImportError::NonPublicDestination { url, address }` names the address; an exhaustive `match` on `OciImportError` must add it. Every request's headers, connecting and the TLS handshake included, now end at `2 × connect_timeout + response_timeout`, enforced on every read and write of the connection: ureq waits up to a second per read once its own phase deadline has passed, so a server sending a header byte at a time was bounded only by the 64 KiB header limit.
