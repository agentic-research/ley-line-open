- **`leyline rootfs import-oci` imports layers whose entry names are absolute, as every Nix `dockerTools` image's are** (bead `ley-line-open-cffbb5`). A store-path layer names its entries `/nix/store/...`, and the import refused the first one ("absolute paths are refused"), so no Nix-built image imported. A leading `/` in an entry name or a hard-link target is now the image root, as containerd and Docker read it: `/nix/store/x` is `nix/store/x`, and an absolute-name layer gives the same rootfs digest as the identical relative-name layer. The traversal rules apply unchanged after that: a `..` component (`/../etc/passwd`, `/a/../../x`) is still refused by name, as are an entry through a link and the root's `rootfs.manifest.json`. Nix images hold links, so under rootfs manifest v1 they import with `--symlinks resolve`.
