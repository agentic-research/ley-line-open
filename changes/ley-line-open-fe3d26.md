Section: Fixed

- **`leyline rootfs import-oci` imports LLO's, mache's and rosary's published images** (beads `ley-line-open-fe3d26`, `ley-line-open-391965`).
  Each was refused whole over an entry the guest could never use: LLO v0.27.0 over the `dev/console` character device and the mode-`0000` `etc/shadow` in its chainguard base, and mache and rosary, under `--symlinks resolve`, over dangling links (`usr/share/doc/apt/NEWS.Debian.gz`, `usr/share/zoneinfo/localtime`). The import now drops such entries, never writes them, and lists each in four new JSON fields. `specialEntriesDropped` lists device nodes and FIFOs strictly beneath `dev/`, `proc/` or `sys/`, which libkrun's guest init mounts kernel filesystems over before the workload runs. `unreadableFilesDropped` lists regular files without their owner-read bit, which no unprivileged reader, the guest's virtio-fs server included, can read. Under `--symlinks resolve`, `linksDroppedKernelMount` lists links into `dev`, `proc` or `sys`, and `linksDroppedDangling` lists links whose target the image does not hold. Still refused by name: devices elsewhere, link loops, a `..` above the image root (also after a missing component), and a directory link containing itself. A directory entry whose owner cannot read it is now refused too, because directories are written `0755` and it would expose what it hides. `--symlinks refuse` stays the default and is unchanged. The rootfs digest is still BLAKE3 over `rootfs.manifest.json`, and a dropped entry is not in it. An image with nothing to drop keeps its digest (hello-world's is unchanged), and the fixture's known answer is unchanged. The runtime README's "Dropped entries" section cites the `init.c` lines behind each rule and states what a guest can observe of each drop.
